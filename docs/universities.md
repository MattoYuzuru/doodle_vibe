# Подключение вузов: ВШЭ, МИСИС и произвольный вуз

Статус: реализовано в `backend/src/sources`, покрыто **фикстурами**. Живой вход в ВШЭ
не выполнялся и не подтверждён: его делает владелец по [инструкции](#живая-проверка-владельцем).
Контракт API — [Backend API v1](backend-api.md), решение — [ADR-0004](adr/0004-universal-source-types.md).

## Что подтверждено анонимными запросами (2026-10-25)

Это публичные GET без входа и без чужих данных. Остальное в этом документе проверено только
синтетическими фикстурами.

| Узел | Факт |
|---|---|
| `edu.hse.ru` | Smart LMS — установка Moodle (в `lib/upgrade.txt` ссылка на `UPGRADING.md`, то есть 4.5+) за защитой QRATOR |
| Вход | `/login/index.php` → `/login/hselogin.php` → OIDC `/auth/oidckc/` (SSO ВШЭ); ссылка на локальную учётную запись `/login/hseloginfull.php` |
| `/login/token.php` | Существует: без параметров отвечает Moodle-ошибкой `missingparam`. Принимает ли он реальный пароль студента — **не проверено** |
| `/webservice/rest/server.php` | Существует: отвечает `invalidtoken` |
| `/admin/tool/mobile/launch.php` | 404 «Ошибка»: запуск мобильного приложения через SSO недоступен |
| `/calendar/export_execute.php` | Существует: неверный токен даёт «Invalid authentication» |
| `ruz.hse.ru` | **Все** пути, включая `/api/...`, из внешней сети перенаправляют на `https://www.hse.ru/eduland/schedule/` с текстом «Доступ к РУЗ осуществляется только из внутренней сети НИУ ВШЭ» (Wi‑Fi HSE.Student, у сотрудников VPN) |

Следствия:

- **SSO/MFA ВШЭ не автоматизируется.** Backend не проходит Keycloak/OIDC, MFA и CAPTCHA и не принимает
  cookies браузера. Это границы безопасности, а не недоработка.
- **РУЗ не проверен вживую:** из внешней сети формат ответа недоступен. Адаптер написан по публичным
  сторонним описаниям API (`/api/search?term=…&type=student`, `/api/schedule/student/{id}?start=YYYY.MM.DD&finish=YYYY.MM.DD&lng=1`,
  поля `date`, `beginLesson`, `endLesson`, `discipline`, `auditorium`, `building`, `kindOfWork`, `lecturer`, `lessonOid`)
  и **требует живой сверки** из сети ВШЭ. При любом отличии формата адаптер возвращает ошибку и не записывает частичный снимок.
- Production-сервер вне сети ВШЭ получит `source_network_restricted` для РУЗ. Ретранслятор/VPN — отдельное решение владельца.

## Способы входа

| Источник | Способ (`authMethods[].id`) | Что вводит студент | Данные | Статус |
|---|---|---|---|---|
| `edu.hse.ru` | `calendar_url` (рекомендован) | Личная ссылка экспорта календаря Moodle | дедлайны, события с временем, курсы по названиям из календаря | фикстуры; вживую не проверено |
| `edu.hse.ru` | `moodle_token` | Токен веб-сервиса Moodle, если он у студента есть | курсы и задания | фикстуры; выдаётся ли токен студентам ВШЭ — не проверено |
| `edu.hse.ru` | `moodle_password` | Логин и пароль **локальной** учётной записи | курсы и задания | только если у студента есть локальный пароль; SSO-пароль не подойдёт |
| `ruz.hse.ru` | `ruz_identifier` | Почта вуза, ФИО или числовой номер из РУЗ | расписание на 7 дней назад и 8 недель вперёд | фикстуры; только из сети ВШЭ |
| `newlms.misis.ru` | `moodle_password`, `moodle_token`, `calendar_url` | как в Moodle | курсы и задания (календарь — ещё и события) | как прежде; фикстуры |
| Любой Moodle | те же три | как в Moodle | см. выше | после положительного определения |
| Любой публичный iCal | без входа | ничего (ссылка в `sourceUrl`) | расписание | фикстуры |
| Любой iCal с токеном в ссылке | `calendar_url` | ссылка целиком | расписание | фикстуры |
| Публичные страницы | без входа | ничего | документы (поиск FTS5, FAQ) | как прежде |

Чего нет: закрытые материалы курсов, оценки и ведомости (нужен вход), чужие данные, запись в системы вуза.

### Как получить ссылку календаря в Moodle (edu.hse.ru)

В браузере после обычного входа: **Календарь → Импорт или экспорт календарей → Экспорт календаря**, события
«Все», период «Рекомендуемые/Пользовательский», затем **Получить URL календаря**. Названия пунктов зависят от версии.
Ссылка содержит личный токен: считай её паролем. Backend хранит её только в зашифрованном секрете, ходит по ней
GET-запросом без редиректов, на том же origin, и вырезает токен из любых сохранённых строк.
Точный способ отзыва ссылки на `edu.hse.ru` не проверен.

Правило разбора Moodle-календаря: событие без длительности — **дедлайн** (`dueAt`), событие с длительностью —
запись **расписания**; курс — название из `CATEGORIES` (идентификаторов курсов Moodle iCal не содержит, ссылки на курс нет).

## Универсальное определение источника

Известные вузы — данные в `backend/src/sources/presets.mjs` (origin, тип исполнителя, порядок способов входа,
часовой пояс), а не ветки `if`. Для любого другого URL:

1. Origin из пресета или сохранённый типизированный адаптер → исполнитель выбран без сети.
2. Публичное чтение: `text/calendar` (или тело `BEGIN:VCALENDAR`) → **iCal**-расписание; адаптер `ical` сохраняется.
3. Источник вида `lms`: HTML-маркеры Moodle либо ответ `/login/token.php` / `/webservice/rest/server.php` в формате
   ошибки Moodle (работает и когда все страницы уходят на SSO) → адаптер `moodle`, `user_action_required` со способами входа.
4. Известные, но неподдержанные LMS (Canvas, Blackboard, Open edX, Brightspace, Sakai) → `source_lms_unsupported` и `lms` в результате.
5. Иначе — прежний путь: JSON/CSV по рецепту, публичный HTML как документы.

Типизированный адаптер хранит только `{version:1,type}`: ни URL, ни полей, ни токенов. Рецепты JSON/CSV остаются
декларативными; произвольный код не исполняется.

Ограничения: Moodle должен быть на корне origin (подкаталог вроде `/moodle/` не поддержан); iCal — только `FREQ=DAILY|WEEKLY`
(`INTERVAL`, `COUNT`, `UNTIL`, `BYDAY`, `EXDATE`, `RECURRENCE-ID`), другие правила дают `source_format_unsupported` без частичной записи;
не более 1000 событий, окно −30…+400 дней; названия часовых поясов Windows не поддержаны.

## Коды `errorCode`, требующие действия пользователя

| Код | Что сделать |
|---|---|
| `source_auth_required` | Ввести данные заново: пароль неверен, токен/ссылка отозваны или нужен SSO |
| `source_network_restricted` | РУЗ доступен только из сети ВШЭ |
| `source_identifier_not_found` / `source_identifier_ambiguous` | Уточнить почту, ФИО или номер; человека backend не угадывает |
| `source_lms_unsupported` | LMS распознана, адаптера нет |
| `source_mapping_required`, `source_format_unsupported` | Формат не распознан однозначно |

## Живая проверка владельцем

Скрипт запускает те же store, очередь, worker и исполнители, что backend, но без Telegram и HTTP. Учётные данные ты вводишь
сам в терминале: ввод секретов скрыт, он не попадает в argv, окружение, историю и вывод; в SQLite секрет лежит
зашифрованным. Данные видны только в твоём терминале и в локальной БД `backend/.live/live-check.sqlite`.

1. Создай отдельный ключ и файл окружения вне репозитория (значение не коммить и не показывай):

```bash
umask 077 && printf 'DATA_ENCRYPTION_KEY=%s\n' "$(openssl rand -base64 32)" > "$HOME/doodle-live.env"
```

2. Для РУЗ подключись к Wi‑Fi **HSE.Student** или VPN ВШЭ; для LMS сеть любая. Запуск:

```bash
npm --prefix backend run live -- --env-file "$HOME/doodle-live.env" --university hse
```

3. Скрипт создаст пространство «НИУ ВШЭ» и два источника: `edu.hse.ru` и `ruz.hse.ru`. Для каждого он покажет способы входа;
выбери номер или Enter, чтобы пропустить. Для LMS выбери «Ссылка экспорта календаря» и вставь ссылку (скрыто); для РУЗ введи почту
вида `логин@edu.hse.ru`. В конце печатаются расписание, дедлайны, курсы и документы пространства.
4. Другой вуз и публичные страницы:

```bash
npm --prefix backend run live -- --env-file "$HOME/doodle-live.env" --url https://timetable.example/group.ics
npm --prefix backend run live -- --env-file "$HOME/doodle-live.env" --document https://www.hse.ru/
```

`--db <путь>` задаёт другую БД, `--limit N` — сколько записей показывать. Повторный запуск создаёт новые пространства в той же БД;
удали `backend/.live/`, чтобы начать с нуля. Если результат отличается от ожидаемого (особенно РУЗ), сохрани только код ошибки из вывода,
без данных.

## Что понадобится frontend

Подключение Mini App к `/api/v1` — отдельная задача. Для этих источников UI должен:

- создавать подключения по `sourceUrl` и после discovery читать `GET /api/v1/connections/:id`: `authMethods[]` (`id`, `type`, `label`, `fields`, `note?`, `notes?`);
- рисовать форму по `fields` и отправлять `POST /connections/:id/auth` ровно с одной формой: `{origin,token}`, `{origin,username,password}`,
  `{origin,calendarUrl}` или `{origin,identifier}`; поля с `password`, `token`, `calendarUrl` — маскированные;
- показывать `note`/`notes` (`moodle_calendar_export`, `local_accounts_only`, `sso_login_only`, `university_network_only`) и инструкцию получения ссылки;
- переводить `errorCode` из таблицы выше в понятный текст и CTA, опрашивать job до `succeeded|failed`;
- выводить `schedule`, `deadlines`, `courses` из общего формата с `fetchedAt`/stale; у курсов из календаря нет ссылки на курс и идентификатора Moodle.
