## DES-001 — направление и интерфейс сотрудничества

- Результат: короткий документ с выбранной иерархией, цветом, типографикой,
  поверхностями, движением и голосом, а также карта общих файлов.
- До двух вариантов сравниваются на одном наборе учебного контента; можно
  аргументированно развить существующий стиль. Timebox обсуждения — 30 минут.
- Приёмка: выбрано направление, роли A/B/frontend не владеют одним файлом
  одновременно; [контракт](contracts.md) уточнён; ограничения DS-001–DS-013 сохранены.
- Проверка: `npm run check`. Большой moodboard без решения не закрывает задачу.

## DES-002 — основы и токены (код, B)

- Область: `theme/tokens.css`, типографика, общие motion-значения; небольшой
  справочник назначения/сочетаний. Текущие экспорты и `--c-*` сохраняются/алиасируются.
- Приёмка: light/dark покрывают text, surface, status, focus, spacing, radius,
  elevation и motion; смена темы не оставляет компонент с чужим фоном;
  нет новых произвольных цветов в мигрируемых компонентах.
- Проверки: `npm run check`, `npm run typecheck`, `npm run build`; таблица
  измеренных контрастов для текста/фона, визуальная проверка обеих тем (DS-001, DS-010).

## DES-003 — UI-kit, ошибки и источники (код, B)

- Область: Button/IconButton, Field, Card/Badge, StatusBanner/SourceStatus,
  Skeleton/EmptyState, SourceCitation и ChatMessage; переиспользовать подходящие
  элементы `components/ui.tsx`, не делать вторую несвязанную библиотеку.
- Приёмка: типизированные props, loading/disabled/focus/error; длинный русский
  текст не ломает layout; источник, stale и время читаются; повторное действие
  не уходит от loading-кнопки. Ни один компонент не делает запрос к LMS.
- Проверки: typecheck/build, синтетические состояния, клавиатура/touch и
  проверка значимых действий через browser fixtures (DS-002, DS-009, DS-012).

## DES-004 — логика маскота (код, A)

- Выделить детерминированный selector/reducer из store-зависимой совы;
  входы/выходы — по [контракту](contracts.md), время передаётся явно.
- Приёмка: reauth/error, activity, unknown/empty, soon/urgent/overdue,
  подтверждённое завершение и смена пространства различимы; ровно 24/72 ч,
  срок в полночь и одинаковые сроки обрабатываются стабильно.
- Проверки: поведенческие unit-сценарии с фиксированным clock, неизвестной
  датой, stale и чужим spaceId; тесты подключены к репозиторной команде (DS-004, DS-009).

## DES-005 — renderer и ресурсный контракт (код, A)

- Переиспользовать текущую сову в `OwlAssistant.tsx`; разделить renderer,
  доступную оболочку и получение данных. Глаза/поза/аксессуар управляются props.
- Приёмка: маленький и крупный размер, две темы, стабильные границы элемента,
  текстовая альтернатива/CTA; missing asset даёт базовый образ, а не пустой экран.
- Проверки: typecheck/build, каталог с контролируемыми props, отсутствие
  запросов из renderer, повторяемый скриншот в static-режиме (DS-003, DS-011).

## DES-006 — «горит дедлайн» и реакции (код, A)

- Реализовать огонь/свечение как urgency-слой с текстом и действием к работе;
  не дублировать пороги `urgency.ts`. Текст поддерживающий, без обвинений.
- Приёмка: urgent включает огонь, done не включает; overdue подписан отдельно;
  несколько работ не порождают несколько сов. Завершение реагирует один раз,
  reload/смена вуза не запускают старую реакцию; reduced/lite/calm статичны.
- Проверки: unit переходов, browser fixtures для одного срока/нескольких/ошибки,
  доступное CTA и отсутствие перекрытия клавиатуры (DS-005, DS-008).

## DES-007 — события и Новый год (код, A)

- Добавить декларативный реестр событий и отдельный аксессуар-шапочку;
  реализовать окно через Новый год и стабильный приоритет пересечений.
- Приёмка: шапочка+urgent совместимы; отключение сезонности оставляет срок/CTA;
  вне окна возвращается базовый образ; неизвестный ресурс даёт fallback.
- Проверки: фиксированные даты 19/20 декабря, 10/11 января, два timeZone,
  пересечение событий, reduced mode и preview в октябре (DS-006, DS-007).

## DES-008 — живая галерея (код, B)

- Сделать локальную проверочную поверхность тех же компонентов и renderer:
  controls для темы, ширины, состояния, даты/часового пояса и режима движения.
  Конкретный entrypoint описать в DEVELOPMENT после его реализации; не выдавать
  будущую команду за существующую и не добавлять обязательную тяжёлую платформу.
- Приёмка: можно показать каждый обязательный случай, включая шапочку+огонь,
  без backend, секретов и реальной даты; фикстуры синтетические, runtime-данные
  production не открываются через preview-переключатель.
- Проверки: typecheck/build, сценарий открытия каталога и смены controls;
  состояния/инструкции связаны с DS-011 и актуальны вместе с кодом.

## DES-009 — доступность и производительность (код, A+B)

- B владеет focus/контрастом/размером целей в UI-kit; A — остановкой движения,
  reduced/lite/calm, visibility и статичным fallback. Каждая часть — отдельный PR.
- Приёмка: 320/390/768 CSS px, 200% текст, клавиатура и safe area; decorative
  sprite не спамит aria-live; настройка спокойного режима реально убирает
  петли/частицы. Скрытая вкладка их не продолжает; отсутствуют таймеры на каждый кадр
  для вычисления дедлайна. Ресурсный бюджет измерен/явно указан пробел.
- Проверки: браузерные сценарии с emulateMedia(reducedMotion), focus, длинным
  текстом и viewport; ручная проверка screen reader/целевого телефона отмечена
  отдельно (DS-008, DS-010), без неподтверждённого заявления WCAG-compliant.

## DES-010 — включение в продукт (код, Frontend)

- Область: экраны, адаптер API→view-model, активное пространство и props
  компонентов/совы. A/B передают готовые экспорты и фикстуры, не меняя эти файлы.
- Приёмка: данные/CTA/состояние совы переключаются вместе с ВШЭ/МИСИС;
  loading не показывает прежний вуз; error/stale/reauth видны без потери
  доступных данных. Существующие карточки остаются рабочими.
- Проверки: typecheck/build, browser fixtures для двух пространств и ошибки;
  согласование контракта с владельцем backend (FR-002, FR-005, DS-004, DS-012).

## DES-011 — визуальные и браузерные проверки (код, B + Frontend)

- Добавить к существующему Playwright набор для состояний каталога и важного
  пользовательского пути. Baselines получаются из фиксированных clock/data,
  остановленного движения и известного браузера, а не из случайного живого экрана.
- Приёмка: обе темы, narrow viewport, urgent+New Year, reauth, stale, reduced
  и смена вуза покрыты выбранными проверками. Скриншоты не заменяют assertions
  текста, CTA и focus. Новая baseline сопровождается просмотром причины diff.
- Проверки: `npm run test:e2e` и сборка; обновление политики/каталога тестов,
  без пропусков и широкого retry для скрытия нестабильности (DS-009–DS-012).

## DES-012 — презентация из реализованной системы (B)

- Подготовить набор сцен/ресурсов из реального каталога: два пространства,
  подключение, срочная работа, sourced-ответ, сезонный образ и статичный fallback.
- Приёмка: слайды/демо используют те же имена состояний и visual tokens;
  реализованное, fixture и планы явно различены. Показано, что A/B сделали
  по коду и как использовали агентов, без раскрытия переписок с личными данными.
- Проверка: репетиция одного основного и одного аварийного сценария; свежие
  ссылки на PR/проверки. Слайды сами по себе не закрывают DES-002–DES-011.
