# Требования к дизайн-системе Doodle

Статус: **целевые требования**, 2026-10-25; новый набор ещё не реализован.
Связь: FR-002, FR-003, FR-005–FR-007, FR-011–FR-013, FR-015–FR-018 и
NFR-001, NFR-007, NFR-013–NFR-014 из [продуктовых требований](../product/requirements.md).
Реестр реализации: [задачи](tasks.md). Техническая схема пока
[предложена](../rfcs/0002-design-system.md).

## Направление и степень свободы

Сохранить узнаваемость Doodle и существующей совы. Пользователь должен быстро
найти ближайшую пару, срок, источник и следующий шаг. Маскот создаёт характер
и помогает ориентироваться; учебные данные остаются главным содержимым.

Команда может предложить до двух существенно разных направлений: иерархия,
плотность, типографика, поверхности, цвет, форма, движение и голос. Сравнить их
на одинаковых четырёх состояниях: расписание, срочный дедлайн, подключение,
ответ чата с источником. Выбор зафиксировать с причинами и стоимостью внедрения.
Существующий визуальный язык является исходной точкой; полная перерисовка
экранов или замена персонажа не требуется для выполнения этих задач.

## Проверяемые требования

| ID | Поведение / ограничение | Наблюдаемый результат |
|---|---|---|
| DS-001 | Единые семантические токены | Цвет, текст, интервалы, радиусы, границы, слои и движение берутся из общего набора; изменение темы не требует правок каждого экрана |
| DS-002 | Полные состояния компонентов | Для каждого интерактивного компонента описаны применимые default/pressed/focus/disabled/loading/error; состояния видны в каталоге |
| DS-003 | Сова переиспользует существующий образ | Пропорции и узнаваемые черты сохраняются в обоих размерах/темах; renderer не читает API и не хранит учебные данные |
| DS-004 | Состояние совы связано с данными | При одних входах и времени результат одинаков; данных другого пространства нет ни в тексте, ни в анимации |
| DS-005 | «Горит дедлайн» | При открытом urgent-дедлайне видны огненный акцент, текст срока и действие к работе; завершённая работа огонь не включает |
| DS-006 | События и образы независимы | Новогодняя шапочка сочетается с функциональным состоянием и не перекрывает читаемость, ошибки или срок |
| DS-007 | Событие настраивается и проверяется | Даты, часовой пояс, приоритет и ресурс заданы в реестре; любой образ можно просмотреть на фикстуре без ожидания нужного месяца |
| DS-008 | Движением управляет пользователь | Системный reduced motion, облегчённый режим и настройка спокойного маскота дают статичный/сдержанный вариант с тем же смыслом |
| DS-009 | Состояния источников честные | Loading, empty, stale, offline, reauth и error визуально различаются; отсутствие данных не выглядит как «всё сдано» |
| DS-010 | Обе темы и мобильная адаптация | Контент читается при ширине 320/390/768 CSS px, увеличении текста до 200%, safe area и открытой клавиатуре |
| DS-011 | Каталог является общей проверочной поверхностью | Те же компоненты/токены, что в продукте, показаны с синтетическими данными; каталог не требует логина в вуз |
| DS-012 | Источник и свежесть видны | Карточка/ответ сохраняет метку вуза, исходную ссылку и время обновления; декоративный слой их не закрывает |
| DS-013 | Презентация использует общую систему | Палитра, типографика, состояния и персонаж происходят из того же набора; mock, реализованное и живое демо подписаны отдельно |

## Токены и UI-kit

Владелец B описывает имена, значения light/dark, назначение, допустимые сочетания
и пример применения. Категории: фон/поверхности, основной/вторичный текст,
акцент/on-accent, info/success/warning/danger, border/focus, spacing, типографика,
радиусы, тени/прозрачность, z-index, duration/easing и размеры touch-target.

Новые значения не размножаются в hex/inline-style по экранам. Для существующих
`--c-*` нужен совместимый переход/alias, а не массовое переименование. Цвет
вуза или сезонный акцент не меняет значения danger/success. Шрифт и иконки
переиспользуются; новый ресурс имеет понятное происхождение и лицензию.

Первый набор компонентов: Button/IconButton, Field и сообщение ошибки,
Card, Badge, StatusBanner/SourceStatus, Skeleton, EmptyState,
SourceCitation, ChatMessage и контейнер маскота. У каждого есть типизированные
props, семантика, размеры, длинный русский текст, обе темы и сценарий ошибки.
Загрузка не меняет неконтролируемо размеры кнопки и не допускает двойное действие.
Навигация, SpaceSwitcher и связывание с API принадлежат frontend, а не UI-kit.

## Состояния маскота и срочность

Модель и renderer разделены; подробности в [контрактах](contracts.md). Обязательные
случаи: idle, connecting, syncing, thinking, ready, empty, offline, reauth,
error, soon, urgent, overdue и краткая реакция на подтверждённое завершение.

| Вход | Представление | Действие |
|---|---|---|
| Идёт подключение/синхронизация | Сдержанная активность, понятный текст этапа; неизвестный прогресс не превращается в выдуманный процент | Открыть состояние / отменить, если отмена поддержана |
| Агент ищет ответ | «Ищу в …» с выбранным вузом, без обещания результата | Вернуться к чату |
| До срока более 72 ч | Спокойное состояние | Ближайшая работа по запросу |
| До срока >24 ч и ≤72 ч | Тёплый акцент «скоро», без непрерывной тревоги | Открыть работу |
| До срока >0 и ≤24 ч | Огонь/тёплое свечение и явный срок; спокойный режим оставляет статичный огненный знак | Открыть срочную работу |
| Срок наступил/прошёл, работа открыта | Отдельное «просрочено», без обвинений и бесконечной паники | Открыть работу |
| Работа подтверждённо завершена | Одна короткая реакция; при reload не повторяется как новое событие | Следующая работа |
| Данных нет/источник недоступен | Empty/offline/error и реальное состояние свежести | Подключить / повторить / войти снова |

Границы 72/24 ч согласованы с текущим `theme/urgency.ts`; расчёт срока использует
общую логику дат, включая `effectiveDue`. Новые пороги меняются как единое
продуктовое правило с тестами, а не внутри анимации. Если доступен только старый
снимок, срочность сопровождается меткой устаревания. У неизвестного/невалидного
срока нет выдуманного countdown. Несколько срочных работ дают одну выбранную
работу и счётчик, а не несколько перекрывающихся персонажей.

Первичный текст/CTA: ошибка доступа или источника → выполняемая операция →
срочная работа → подтверждённая реакция → обычный контекст. Срочность остаётся
дополнительным бейджем при первичной ошибке/операции. Сезонный образ всегда
декоративный слой. Праздничная реакция не перекрывает reauth/offline/error.

## Реестр событий

Первое сезонное событие: **Новый год** — шапочка на существующей сове и небольшой
декоративный акцент. Предлагаемое окно: с 20 декабря 00:00 включительно до
11 января 00:00 исключительно в часовом поясе активного пространства
(для стартовых московских сценариев — Europe/Moscow). Переход через год явный.

Реестр расширяем: `eventId`, окно дат, `timeZone`, `priority`, `skinId`,
ресурс и статичный fallback. При пересечении выбирается максимальный priority,
затем стабильный eventId. Настройка отключает сезонность; настройка движения
независима от неё. После окна возвращается обычный образ. Будущие события
добавляются записями/ресурсами; «маскот в огне» остаётся состоянием дедлайна,
а не календарным событием. Произвольные JS-сниппеты и сетевые загрузки правил
не являются форматом реестра. Персональные праздники не требуют сбора даты
рождения для этого MVP.

## Доступность, движение и ресурсы

- Текст: контраст ≥4.5:1 для обычного и ≥3:1 для крупного текста. Проверять
  итоговый фон, включая градиент/прозрачность; это цель, а не заявление о
  соответствии текущей версии. [WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
- Продуктовый минимум основных touch-target — **44×44 CSS px**; это наше
  требование, более строгое, чем базовые 24×24 с исключениями в
  [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).
- Статус передаётся текстом/иконкой, не только цветом. Есть клавиатура,
  видимый focus, подписи кнопок; важное действие доступно без hover/долгого нажатия.
- Декоративный renderer скрыт от screen reader; смысл и CTA доступны отдельно.
  `aria-live` не объявляет каждую секунду countdown/каждый кадр анимации.
- При [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion),
  lite или явном спокойном режиме убрать пульсацию, тряску, частицы и петлю огня.
  Статичный огонь/бейдж сохраняет информацию. Не использовать вспышки и резкие
  изменения яркости; декоративное движение можно остановить.
- Один постоянно анимируемый маскот на экране; остановка при скрытии вкладки/
  неактивном Mini App, возврат без повторного проигрывания старого завершения.
  [События платформы](https://core.telegram.org/bots/webapps).
- Сова не закрывает ввод чата, клавиатуру, CTA, навигацию или ссылки, не
  перехватывает прокрутку невидимым слоем. Safe area сохраняется в обеих темах.
- SVG/CSS/существующий motion — исходный вариант. Новый renderer/библиотека
  требует конкретного обоснования и fallback. Предлагаемый бюджет одного
  сезонного набора — ≤250 KiB переданных сжатых ресурсов с отложенной загрузкой;
  бюджет проверяется по факту, это не замер текущего приложения.
- Отсутствующий/повреждённый ресурс возвращает базовую сову; backend и работа
  с учебными данными не зависят от доступности картинки/анимации.

## Приёмочные примеры

| Сценарий | Ожидаемый результат |
|---|---|
| 25 декабря, открытая работа через 12 ч | Шапочка + огненный акцент + текст срока; доступна ссылка на работу |
| То же при reduced motion | Шапочка/огонь статичны, та же информация и действие |
| То же при reauth | Первична просьба войти снова; старый срок подписан как устаревший, нет праздничного overlay |
| 19 декабря 23:59 → 20 декабря 00:00 | Смена базового образа на новогодний по заданному timeZone |
| 10 января → 11 января 00:00 | Возврат базового образа, срочность не сброшена |
| Переключение ВШЭ → МИСИС | Предыдущие title/CTA/реакция сразу убраны; до нового снимка состояние unknown/loading |
| Sync завершился ошибкой и вернул старый снимок | Старые данные видны как stale; «всё сделано» не показывается |
| Отключена сезонность | Базовая сова с сохранёнными urgency, текстом и CTA |

Любой новый образ сопровождается normal/reduced/lite, light/dark, fallback и
детерминированным примером. Скриншоты фикстур не считаются доказательством
живого Telegram, входа в вуз, полной доступности или измеренной производительности.
