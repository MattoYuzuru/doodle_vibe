# Контракты дизайн-системы

Статус: **Proposed**, код контрактов ещё не введён. Это общий ориентир для
DES-001–DES-010, не описание уже работающего API. Входы backend согласуются
отдельно с владельцем frontend; новые учебные endpoints здесь не придумываются.

## Границы и владение

| Область | Владелец | Код сейчас / предполагаемая точка изменения |
|---|---|---|
| Токены, типографика, общие motion-значения, UI-kit | B | `theme/tokens.css`, `theme/fonts.ts`, `theme/motion.ts`, `components/ui.tsx`; новые presentational-компоненты рядом, по согласованной структуре |
| Состояния/ресурсы/renderer совы, календарный реестр | A | `components/OwlAssistant.tsx`; выделяемые `theme/assistant-state.ts`, `theme/events.ts`, `components/assistant/` |
| Экраны, навигация, активное пространство, DTO→view-model | Frontend | `App.tsx`, `screens/`, `store/`, API-клиент, wiring UI-kit/маскота и обработка действия |
| Авторизация, доступ, sync, источники, retrieval | Backend | Сервер и интеграции; дизайнерские задачи не меняют секреты, БД или внешние действия |

Пути новых модулей — предложение; один владелец утверждает итоговые имена в
задаче, обновляет ссылки и не создаёт параллельную копию одной сущности.
`theme/urgency.ts`/`lib/dates.ts` остаются общим источником вычисления срочности.
Менять их семантику можно только совместно с frontend/backend и её тестами.

## Модель поведения

Реализовано в DES-004: [`theme/assistant-state.ts`](../../jarvis-app/web/src/theme/assistant-state.ts),
тесты — [`web/tests/assistant-state.test.mjs`](../../jarvis-app/web/tests/assistant-state.test.mjs)
(`npm run test:web`). Отличия от исходного предложения ниже: персонаж выбирается
по пространству (ВШЭ — ворона Варя, МИСИС — сова Дуся, остальные — Дуся),
к intents добавлены `retry` и `connect` для ошибок и пустого состояния,
в контекст — необязательный `acknowledgedEventIds` для дедупликации реакции.
Реестр событий (`eventRegistry`) добавит DES-007 вторым параметром конфигурации.

Предлагаемый `AssistantContext` содержит:

```ts
type AssistantContext = {
  spaceId: string;
  nowMs: number;
  timeZone: string;
  availability: "ready" | "unknown" | "empty" | "offline" | "reauth" | "error";
  activity: "idle" | "connecting" | "syncing" | "thinking";
  snapshot: {
    spaceId: string;
    updatedAt: number;
    stale: boolean;
    deadlines: readonly {
      id: string; title: string; dueMs: number | null; done: boolean;
    }[];
  } | null;
  recentEvent: {
    id: string; spaceId: string; kind: "deadline-completed"; at: number;
  } | null;
  preferences: {
    seasonal: boolean;
    motion: "system" | "calm";
  };
  reducedMotion: boolean;
  lite: boolean;
  visible: boolean;
};
```

`resolveAssistantPresentation(context, eventRegistry)` — чистая функция без
запросов, чтения stores/DOM/localStorage, скрытого `Date.now()` и случайности.
Время, свойства доступности и активное пространство приходят явно. Несовпадение
`snapshot.spaceId`/`recentEvent.spaceId` с активным пространством отбрасывает
такой вход. `done` адаптируется из существующего статуса задания, даты — из
общей модели; парсер срока не переносится в renderer.

Результат описывает первичный статус, urgency (включая unknown), skin, текст,
доступное действие и режим движения. Функция возвращает типизированный intent
(`open-deadline`, `open-source`, `open-chat`, `reauth`), а обработчик frontend
разрешает его в действующее действие. Renderer не выполняет intent сам.
При равных сроках выбор стабилен по ID; приоритеты — в
[требованиях](requirements.md), не в нескольких независимых switch по экранам.

Проверка принадлежности props не заменяет серверную авторизацию. Маскоту
не передают creds, cookies, полный профиль, ответы сервера с секретами или
содержимое истории чата. Учебный контекст остаётся оперативными props, а не
записью в глобальном реестре образов.

## Представление и временные эффекты

Предлагаемое разделение: семантическое состояние → поза/выражение → urgency-
акцент → сезонный аксессуар. Новогодняя шапочка и огонь могут сосуществовать.
Несколько аксессуаров одного слота не накладываются; слот головы выбирает один
образ по стабильному приоритету. Текст/CTA и focus не зависят от декоративного
ресурса. Базовая сова доступна при любой ошибке ресурса.

Renderer получает presentation и размер; доступная оболочка — подпись, CTA,
настройки и callback intent. Время реакции, смена темы и состояния не меняют
бесконтрольно размер layout. Реакция на завершение краткая (цель ≤1.5 с),
дедуплицируется по пользовательскому пространству и event ID; начальный
снимок со сданными работами не создаёт новые реакции. Событие не проигрывается
повторно после reload/возврата вкладки. Reduced/lite/calm оставляют статичное
подтверждение; `visible=false` останавливает декоративные петли.

Пользовательские настройки движения/сезонности хранятся frontend по принятому
контракту профиля/локальных предпочтений. Компонент не создаёт новое несогласованное
глобальное хранилище. При смене пространства сбрасываются прежние intents,
подписи и временные реакции до получения нового снимка.

## Передача между участниками

B передаёт имена токенов, таблицу вариантов и готовые props компонентов;
A — типы контекста/presentation, renderer, реестр событий и фикстуры состояний.
Frontend подключает их к реальным stores через один адаптирующий слой.
Изменение props согласуется в небольшой контрактной правке, а не угадывается
в трёх ветках. Совместимость существующих экспортов сохраняется до миграции.

Детерминированные фикстуры: urgent, soon, overdue, done-once, no-data, stale,
reauth+urgent, thinking, две темы, New Year+urgent, reduced/lite и смена вуза.
Никаких личных выгрузок для дизайн-каталога. Сценарии визуализации не создают
обход авторизации и не включаются скрытым production-переключателем к реальным
данным. Для теста календаря clock/skin задаётся в локальном каталоге/фикстуре.
