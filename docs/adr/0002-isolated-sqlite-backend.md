# ADR-0002: отдельный backend с SQLite и ограниченными исполнителями

Статус: Accepted — реализация по поручению владельца 2026-10-25.
Реализация: partial; live SSO и frontend cutover требуют отдельной приёмки.
Связан с [ADR-0001](0001-preserve-ui-replace-backend.md),
[контрактом](../architecture/backend-contract.md), [API](../backend-api.md).

Новый сервис Node 24 живёт в `backend/`; native SQLite WAL/FTS5 хранит пространства,
подключения, зашифрованный доступ, полные снимки, документы, память и leased jobs.
Ключ AES-256-GCM находится вне БД. AAD связывает пользователя/пространство/подключение.
SQL/FTS выполняет ACL до выдачи. Устаревший worker не может записать результат:
assertion и изменение находятся в одной SQLite-транзакции с fencing token.

Общие версионированные адаптеры содержат только проверенный декларативный рецепт.
Модель предлагает структуру; исполнитель ограничивает URL, методы, размеры,
время, DNS/IP и redirect. Токены подставляются для точного origin. Частная
страница не передаётся в discovery-модель и не публикует общий адаптер.
Произвольный сгенерированный код на сервере не исполняется.

Вместо переноса legacy server целиком сохраняем его для отката и публикуем v1
контракт фронтенду. Это исключает неявную загрузку старых локальных ключей,
журналов и student state. Миграции личных данных из старой версии пока нет.

Вместо отдельной очереди/векторной БД MVP использует SQLite и один worker.
Это проще для одного сервера; рост нагрузки, распределённый rate limit,
embeddings и дополнительные форматы вводятся по измеренной необходимости.
Несовместимые миграции не допускаются без отдельного плана восстановления.
