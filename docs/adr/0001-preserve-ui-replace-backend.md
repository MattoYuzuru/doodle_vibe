# ADR-0001: сохранить Mini App и бота, заменить backend

- Статус решения: **Accepted**
- Дата: 2026-10-25
- Основание: пользователь подтвердил изменение существующего `doodle_vibe`,
  сохранение бота/UI и возможность использовать API вузов.
- Реализация целевой версии: **not started** на момент записи.
- Требования: FR-002–FR-013, NFR-001–NFR-004.
- Проработка: [RFC-0001](../rfcs/0001-multi-university-platform.md).

## Контекст

Существующее приложение агрегирует данные МИСИС. Полезны интерфейс, транспорт
Telegram, нормализация расписания и чтение таблиц. Backend и модели клиента
существенно связаны с конкретным Moodle и одной структурой профиля.
Следующая версия должна поддерживать несколько вузов у одного студента.

## Решение

Сохраняем React Mini App, бота и пригодные функции, заменяя backend и вводя
контракты источников. Первыми интеграциями являются ВШЭ и МИСИС. ЦУ не входит в
начальный объём. API вузов разрешены; браузерный доступ служит отдельным способом
получения данных там, где это необходимо и разрешено.

Не превращаем один успешный личный вход в общую учётную запись. Переиспользуются
правила адаптера; сессии и права остаются пользовательскими.

## Альтернативы

- Полностью переписать интерфейс и backend: больше работы до первого результата,
  теряются готовые пользовательские сценарии.
- Только параметризовать URL текущего Moodle: недостаточно для нескольких
  пространств, независимых источников, разных схем входа и доступа к памяти.

## Последствия

Нужны общие модели и замена зависимостей клиента от Moodle. Переход выполняется
вертикальными сценариями с контрактными тестами. Существующий runtime не
перезапускается и не публикуется автоматически вслед за изменением документов.
Выбор SQLite, детали секретов, discovery и retrieval пока предложены в RFC;
этот ADR не утверждает их реализацию или безопасность.
