# ADR-0004: типизированные источники, пресеты вузов и новые формы входа

- Статус: Proposed — принятие за владельцем решения; код реализован по поручению задачи «ВШЭ и универсальные источники».
- Дата и основание принятия: не принято; основание — поручение расширить backend для ВШЭ и произвольного вуза без релиза.
- Реализация: implemented в `backend/src/sources`; проверено только фикстурами, живой вход ВШЭ не выполнялся.
- Связанные FR/NFR, RFC и issue: FR-004, FR-008, FR-009, NFR-002, NFR-004; [RFC-0001](../rfcs/0001-multi-university-platform.md), [ADR-0002](0002-isolated-sqlite-backend.md).
- Supersedes / Superseded by: нет; уточняет ADR-0002 (общие версионированные адаптеры).

## Контекст

Встроенный путь знал только МИСИС (`origin === 'https://newlms.misis.ru'`) и Moodle, определённый по публичной
странице. Анонимная проверка `edu.hse.ru` показала: Moodle за SSO, на странице входа нет маркеров Moodle, мобильный
запуск через SSO отключён, зато существуют `token.php`, веб-сервис и экспорт календаря. РУЗ (`ruz.hse.ru`) отвечает только
из сети ВШЭ. Подробности — [universities.md](../universities.md).

## Решение

1. **Пресеты — данные** (`sources/presets.mjs`): origin → тип исполнителя (`moodle`, `ical`, `ruz`), порядок способов входа,
   коды-заметки, часовой пояс. Пресет не даёт доступа и не обходит сетевые проверки.
2. **Типизированный адаптер** `{version:1,type}` сохраняется в существующей таблице `adapters` после положительного определения
   (Moodle: структурированная ошибка `token.php`/`server.php` либо маркеры; iCal: `text/calendar`). Он называет исполнитель из кода
   backend и не содержит URL, полей или значений пользователя. Схема SQLite **не меняется**.
3. **Новые формы входа** в `POST /connections/:id/auth` (ровно одна): `{calendarUrl}` и `{identifier}` рядом с существующими
   `{token}` и `{username,password,service?}`. Обе хранятся только в зашифрованном секрете того же подключения
   (AAD связывает пользователя/пространство/подключение). `calendarUrl` — HTTPS, тот же origin, без credentials/fragment.
4. **Секретный URL**: новый режим транспорта `secretUrl` — только GET, обязательный `boundOrigin`, без редиректов и заголовков
   клиента; запрет query-токенов в обычных URL сохраняется. Токен вырезается из сохраняемых строк.
5. **`authMethods`** в `GET /connections/:id` теперь содержит формы входа исполнителя (`id`, `type`, `label`, `fields`, `note?`, `notes?`),
   затем OAuth-провайдеры оператора. Новые коды `errorCode`: `source_network_restricted`, `source_identifier_not_found`,
   `source_identifier_ambiguous`, `source_lms_unsupported`.
6. **Границы**: SSO/MFA/CAPTCHA не обходятся (пункт уточнён [ADR-0005](0005-remote-browser-login-and-learned-recipes.md): SSO проходит человек в удалённом браузере); токены и cookies браузера не принимаются; человек в РУЗ не угадывается;
   неполный ответ не заменяет прежний снимок.

## Альтернативы

- Ветки `if (origin === …)` для каждого вуза — требуют релиза на каждый вуз; отклонено.
- Приём cookies SSO или автоматизация Keycloak — небезопасно и нарушает границы доступа; отклонено.
- Хранить feed-URL как `sourceUrl` — токен попал бы в публичные поля и логи; отклонено.
- Новая таблица источников — миграция без необходимости: `adapters` и `secrets` достаточно.

## Последствия и проверка

- Frontend получает расширенный контракт `authMethods` и две формы входа (см. universities.md).
- Фикстуры проверяют: изоляцию пользователей, отсутствие токена в снимках/ответах, привязку к origin, отсутствие редиректов,
  сохранение прежнего снимка при ошибке, определение Moodle за SSO, iCal-разбор и неоднозначность РУЗ.
- Не подтверждено: формат ответа РУЗ (недоступен вне сети ВШЭ), приём реального пароля `token.php` на `edu.hse.ru`, содержимое
  календарного экспорта реального студента. Расхождение с реальностью исправляется данными фикстур и разбором, не обходом защиты.
