# Требования к следующей версии

Статус: **целевой MVP, реализация поэтапная**. Обновлено: 2026-10-25.
Требование в таблице не является утверждением, что текущий код ему соответствует.

Существующий продукт — приложение для МИСИС с Node.js backend и React Mini App.
Зафиксированное направление — новый backend при сохранении интерфейса и бота.
ВШЭ и МИСИС имеют первый приоритет; ЦУ и другие вузы добавляются позже.

## Функциональные требования

| ID | Поведение | Критерий приёмки |
|---|---|---|
| FR-001 | Вход в платформу по проверенной идентичности Telegram | Сервер отклоняет поддельную, истёкшую или отсутствующую авторизацию защищённого запроса |
| FR-002 | Несколько пространств вузов у пользователя | Через `+` добавляются два пространства; переключение меняет расписание, подключения, FAQ и контекст чата |
| FR-003 | Несколько источников в пространстве | Можно независимо подключить LMS, расписание и документ/таблицу; отказ одного не блокирует остальные |
| FR-004 | ВШЭ и МИСИС как первые интеграции | Для разрешённых тестовых аккаунтов документирован способ входа и фактическое покрытие данных; недоступные поля не выдумываются |
| FR-005 | Управление отдельным подключением | Видны состояния подключения, синхронизации, ошибки и необходимости повторного входа; секрет не возвращается клиенту |
| FR-006 | Учебные данные в общем формате | Курсы, события расписания и задания имеют идентификатор источника, исходную ссылку и время получения; записи двух источников не сталкиваются |
| FR-007 | Повторная синхронизация | Перезапуск не требует входа, пока сохранённый доступ действителен; частичная ошибка не удаляет успешный прежний снимок |
| FR-008 | Переиспользование поддержки источника | Версионированный адаптер установки используется разными пользователями с их собственными подключениями и правами |
| FR-009 | Фоновое исследование неизвестного источника | Пользователь видит ход/результат; кандидат адаптера проверяется до общего применения, сообщает поддержанные сценарии и ограничения |
| FR-010 | Таблицы и документы | Подключённый разрешённый файл/URL обрабатывается с происхождением данных; неоднозначный студент/столбец не угадывается |
| FR-011 | Чат по личным данным | Вопрос о парах получает ответ из структурированных данных нужного доступного пространства, с датой и временем обновления |
| FR-012 | FAQ и поиск по документам/сайтам | Ответ ссылается на источник и его свежесть; при отсутствии подтверждения агент говорит о пробеле и может выполнить ограниченный поиск |
| FR-013 | Долговременная память | История и личные сведения разделены по пользователям/пространствам; публичный FAQ не пополняется личным ответом или неподтверждённой генерацией |
| FR-014 | Отключение и удаление | Отключение прекращает задания и доступ подключения; удаление данных распространяется на связанные снимки, память и поисковый индекс по документированной политике |

## Нефункциональные требования

Это **цели и приёмочные ограничения**, а не результаты измерений существующей
версии. Конкретная задача указывает набор данных, runtime и измеряемый сценарий.

| ID | Ограничение | Проверка |
|---|---|---|
| NFR-001 | Изоляция пользователя, пространства и подключения на сервере | Отрицательные тесты чтения, поиска, чата, синхронизации и подмены ID между двумя пользователями и двумя пространствами |
| NFR-002 | Секреты шифруются аутентифицированным шифрованием; ключ отделён от БД | Тест сохранения/чтения, неверного ключа и контекста; проверка отсутствия plaintext и секретов в публичных ответах/логах |
| NFR-003 | Модель не получает креды и не выбирает произвольный секрет | Исполнитель связывает инструмент с авторизованным подключением; в перехваченном запросе модели нет пароля/cookie/token |
| NFR-004 | Общие адаптеры не содержат пользовательских значений | Проверка схемы и редактированных фикстур; токены, CSRF, подписанные URL и реальные ID не переносятся из наблюдений в шаблон |
| NFR-005 | Ошибка источника изолирована | При timeout/401/403/429/5xx другой источник продолжает работать; повторы ограничены и не создают бесконечный цикл входа |
| NFR-006 | Ограниченная нагрузка и конкуренция | Одновременные запросы не дублируют одну sync/discovery/refresh-операцию; соблюдаются лимиты источника и пауза отказа |
| NFR-007 | Прослеживаемость и свежесть | У каждого снимка/фрагмента известны источник, время получения и область доступа; устаревание видно в UI и ответе чата |
| NFR-008 | Скорость локального чтения | Цель для MVP: p95 ≤ 2 с для 100 последовательных запросов к сохранённому расписанию на зафиксированной fixture-БД; сетевой sync измеряется отдельно |
| NFR-009 | Восстановление после перезапуска | Прерывание фоновой задачи не повреждает последнюю запись; повторный запуск идемпотентен, состояние задания объяснимо |
| NFR-010 | Воспроизводимый clone-to-check | Задокументированные проверки проходят с lockfile на чистом поддержанном runtime без реальных секретов и личных путей автора |
| NFR-011 | Проверяемый ответ агента | Фактическое утверждение о процедуре/вузе имеет проверяемое основание; неоднозначность пространства или противоречие источников не скрывается |
| NFR-012 | Наблюдаемость без секретов | Ошибка содержит код, ID задания и источник; логи/CI-артефакты исключают креды и персональные выгрузки |

## Приёмка MVP и границы

Обязательный путь: бот → Mini App → два пространства → подключение источника →
реальные данные ВШЭ/МИСИС в пределах подтверждённого покрытия → повторное
открытие → вопрос чату о своём расписании и публичном документе.

Fixture-проверки выполняются до live-проверки. Live-проверка проводится только
с разрешёнными аккаунтами и не подменяется демо-данными. Если вуз требует MFA,
CAPTCHA, недоступную сеть или участие пользователя, состояние показывается явно.

В MVP не входят деплой, автоматическая отправка заявлений/работ, выполнение
учебных заданий, гарантированное подключение любого сайта и подключение ЦУ.
Добавление источника может быть экспериментальным; один успешный вход не
доказывает покрытие всех студентов, факультетов и сценариев этого вуза.
