# RFC-0001: пространства вузов и подключаемые источники

- Статус: **Proposed**
- Дата: 2026-10-25
- Реализация: **not started**; существующий backend остаётся исходной системой.
- Основание: [ADR-0001](../adr/0001-preserve-ui-replace-backend.md).
- Требования: [FR/NFR](../product/requirements.md).

## Предложение

Начать с одного Node.js backend, SQLite и ограниченного браузерного worker.
Переиспользовать Mini App/бота и пригодные парсеры через общие контракты.
ВШЭ и МИСИС — первые установки; не обещать работоспособность неизвестного вуза
до исследования с разрешённым доступом.

```text
Telegram / Mini App → API → учебные снимки и память
                         → очередь sync → адаптер → источник
                         → чат → ограниченные инструменты чтения / поиска
Discovery → кандидат адаптера → проверки → версия адаптера
Secrets → только исполнитель подключения
```

## Данные и владельцы

| Сущность | Область и назначение |
|---|---|
| User | Проверенная идентичность платформы |
| Space | Принадлежащее пользователю пространство вуза; вузов может быть несколько |
| Source installation | Конкретный сайт/установка, тип и разрешённые домены |
| Space source / Connection | Привязка источника и пользовательского доступа к пространству |
| Adapter version | Шаблоны чтения, пагинация, маппинг и проверенное покрытие установки |
| Snapshot | Нормализованные курсы, задания, расписание; источник и время получения |
| Document / Chunk | Текст, происхождение, свежесть и область доступа для поиска |
| Conversation / Memory | Личная история/явные факты пользователя в пространстве |
| FAQ entry | Подтверждённый ответ со ссылками и версией источника |
| Job | Sync/discovery с состоянием, владельцем, ограничением времени и повторов |

ID записи включает источник. Общий адаптер не содержит секретов, персональных
ID, реальных ответов студента, подписанных URL или захваченных заголовков.
Временные значения вычисляет исполнитель в контексте текущего подключения.
Для таблицы дополнительно версионируется маппинг структуры, потому что одинаковый
вход не означает одинаковые колонки.

## Доступ и секреты

Пользовательские права определяет backend по проверенной идентичности, а не
модель или параметр запроса. На чтение, поиск, чат и sync распространяется
проверка принадлежности пространства и подключения. Общий кэш возможен только
для явно публичных/допустимых к совместному использованию данных.

Предпочитаем сохранять сессию/token вместо пароля, где это допускает источник.
Необходимые секреты шифруются с проверкой целостности и привязкой к контексту;
мастер-ключ хранится вне SQLite, Git и резервных копий данных. Отдельный
исполнитель получает секрет по внутренней ссылке и ограничивает домены/операции.
LLM, RAG, клиент и общие шаблоны секретов не получают. Шифрование копии БД не
защищает от полностью скомпрометированного процесса с доступом к ключу.

Конкретный способ хранения ключа, ротация, восстановление и политика удаления
должны быть выбраны перед реализацией хранилища; это открытое решение RFC.

## Sync и discovery

Для известных установок запускается обычный детерминированный адаптер.
Для неизвестной — одно ограниченное исследование на установку и наблюдаемое
покрытие; состояние видно пользователю. Кандидат проходит схему, проверки
безопасного чтения, фикстуры и разрешённые проверки интеграции перед общим
применением. Один аккаунт не доказывает покрытие всех ролей/факультетов.

Sync получает данные регулярно, discovery повторяется при изменении структуры
или ошибке контракта. Повторы ограничены; refresh одного подключения не
выполняется одновременно несколькими задачами. Протухшая сессия требует
повторного входа. MFA/CAPTCHA не обходятся. Частичная ошибка сохраняет последний
успешный снимок и его явный статус устаревания.

## Чат, FAQ и память

Расписание и дедлайны читаются инструментами по структурированным данным.
Документы ищутся после серверной фильтрации доступа; при нехватке данных
выполняется ограниченный поиск по источникам выбранного вуза. Для MVP подходит
полнотекстовый поиск SQLite; необходимость embeddings измеряется позже.

Ответ имеет источники и свежесть. История разговора не равна подтверждённому
факту. Личный ответ не становится публичным FAQ. Страница или документ не
может дать агенту право выполнить запись, открыть секрет или сменить инструкции.
Удаление распространяется на связанные документы, фрагменты и индекс.

## Переход и проверка

1. Ввести контракт идентичности, пространства и снимка, проверив два пользователя.
2. Подключить МИСИС через существующие функции и ВШЭ через проверенный способ входа.
3. Перевести экраны на общий формат, сохранив читаемый статус ошибки источника.
4. Добавить чат с инструментами чтения и подтверждённый FAQ.
5. Подключить discovery неизвестного источника как экспериментальный сценарий.

Приёмка и уровни доказательств описаны в [тестировании](../TESTING.md).
Фикстуры не доказывают живой SSO. Для отката сохраняется прежняя версия и схема;
перед миграцией нужны проверка совместимости и резервная копия без раскрытия данных.

## Открытые вопросы

- Подтверждённые способы входа и покрытие источников ВШЭ/МИСИС, ограничения сети.
- Способ пользовательского участия во входе из Telegram и обработка MFA.
- Поставщик ключа, ротация, восстановление, удаление и срок хранения памяти.
- Условия допуска кандидата адаптера и отката его версии.
- Размеры документов, расписание обновления и бюджет внешних запросов/модели.

Деплой и выбор production-инфраструктуры не входят в этот RFC.
