# Отдельная учётная запись Windows для агента лаб — по шагам

Подробная версия шага 4а из ПЕРЕНОС.md (16 окт 2026, владелец: «чтобы никто не смог нанести вред компьютеру или сломать
его через команды»).

## Зачем
Агент лаб (OpenClaw, агент `files`) выполняет команды на ПК. Сейчас он работает под вашей учётной записью `User`, то есть
может всё, что можете вы: ваши файлы, ключи и токены приложения, настройки. Сторож и правила — это проверка текста команд;
обойти её можно. Отдельная учётная запись — проверка самой Windows: обычный (не администратор) пользователь не может
менять систему, программы, чужие профили и процессы других пользователей, что бы ему ни написали.

## Где делать: на новом ПК
Агенту нужен свой экран: LTspice снимается с экрана (иначе `lt_shot.py` даёт код 5), Word и Docker Desktop — программы с
окнами. На новом ПК экран можно отдать агенту: Windows сама входит под `doodle-agent`, а ваш сервер работает в фоне. На
ноутбуке экраном пользуетесь вы, поэтому там этот вариант не подходит (агент без экрана не сделает снимки схем).

## Как будет устроено
| Кто | Что работает | Как запускается |
|---|---|---|
| `User` (вы, администратор) | сервер Doodle, туннель, сторож приложения | задачи Планировщика «выполнять для всех пользователей» — без входа на экран |
| `doodle-agent` (обычный) | OpenClaw Gateway и агент лаб, Docker Desktop, WSL, LTspice, Word | автовход в Windows, Gateway — задача «при входе doodle-agent» |

Сервер отправляет агенту задания так же, как сейчас (через `openclaw agent` на 127.0.0.1:18789), а агенту при этом
закрыты: папка приложения `jarvis-app` (кроме готовых скриптов в `assets`), ваш профиль `C:\Users\User` (кроме
`moodle-work`), системные папки и настройки.

## Ваши шаги (нужны права администратора; пароли вводите только сами, не в чат)
1. **Учётная запись.** Параметры → Учётные записи → Другие пользователи → Добавить → «У меня нет данных для входа этого
   человека» → «Добавить пользователя без учётной записи Майкрософт». Имя `doodle-agent`, пароль придумайте и сохраните
   у себя. Тип — «Обычный пользователь» (не администратор).
2. **Docker Desktop** ставьте «для всех пользователей» (обычная установка в `Program Files`) и добавьте `doodle-agent` в
   группу `docker-users` (это сделает мой скрипт из шага 3).
3. **Права на папки.** В окне «Windows PowerShell (администратор)»:
   `powershell -ExecutionPolicy Bypass -File "C:\Users\<вы>\moodle-work\jarvis-app\ops\migrate\agent-account\1-права.ps1"`
   Скрипт сначала печатает план и спрашивает «да/нет»; посмотреть план без изменений — добавить `-PlanOnly`. Он:
   - добавит `doodle-agent` в `docker-users`;
   - в корне `moodle-work` даст ему только чтение, а внутри (папки лаб, `tools`, новая `agent-shared` для замков и списка
     WSL-пользователей) — чтение и запись;
   - закроет ему `jarvis-app` целиком, оставив только чтение `assets`, папки сторожа и `ops\migrate\agent-account`;
   - закроет всё остальное в корне `moodle-work`: `ops`, историю git, ваши личные папки и файлы (`cmp`, `kompas-lab1`,
     `mo-lr3`, `mo-lr3-v20`, `promo-video`, `tmp`, архив, `HANDOFF.md`, `active-courses.txt`…) и папку копий из
     `backup.json`; создаст закрытую пустую `C:\node_modules`;
   - про диски, открытые на запись всем (часто D:), спросит отдельно; предупредит о папках из PATH, куда может писать любой;
   - создаст задачи «OpenClaw Gateway» (от имени `doodle-agent`, при входе; прежняя ваша сохранится в `export\`) и
     «Doodle Gateway Restart» (её может только запускать сервер, когда Gateway завис);
   - выгрузит настройки агента `files` без токенов в `agent-account\export\` и запишет `jarvis-app\agent-account.json`
     (по нему сервер ищет журналы и настройки агента в его профиле);
   - напечатает итог `icacls`: что открыто и что закрыто.
4. **Первый вход под `doodle-agent`** (выйти из своей учётки или «Сменить пользователя»):
   - WSL: установить Ubuntu (`wsl --install -d Ubuntu`), включить systemd, поставить git, python3;
   - Docker Desktop: открыть, «запускать при входе», включить интеграцию с Ubuntu;
   - двойной щелчок по `ops\migrate\agent-account\2-агент.cmd`: поставит OpenClaw и Claude Code для этой учётки,
     Python-пакеты и библиотеку LTspice, заведёт агента `files` по выгрузке (без ваших токенов), настроит Gateway и его
     задачу, подключит сторожа в настройках Claude Code этой учётки; в конце проверит Docker и WSL;
   - вход в подписку Claude: `claude setup-token`, затем `openclaw models auth login --provider anthropic --method
     setup-token --agent files` и `openclaw gateway restart` — токен вставляете сами в окно терминала (как 30 сент.).
5. **Ваш вход (`User`).**
   - Ещё раз `1-права.ps1` от администратора: теперь профиль агента есть, и скрипт даст вашей учётке чтение журналов
     агента (учёт расхода) и его настроек Claude Code (проверка сторожа).
   - Двойной щелчок по `3-ключ.cmd` (обычный запуск): перенесёт ключ Gateway агента в ваши настройки OpenClaw (ключ не
     показывается), проверит связь и удалит файл передачи.
   - В Планировщике у задач «Jarvis App Server», «Jarvis Tunnel», «Jarvis App Watchdog» поставить «Выполнять для всех
     пользователей» (Windows спросит ваш пароль). Задачу «OpenClaw Gateway» скрипт уже перевёл на `doodle-agent`.
6. **Автовход под `doodle-agent`**, сон «никогда», экран не блокировать — только для этой учётки. Удалённый доступ —
   AnyDesk / RustDesk (не RDP: он блокирует экран).
7. **По желанию (Windows Pro):** `secpol.msc` → Локальные политики → Назначение прав пользователя → «Завершение работы
   системы» — оставить только «Администраторы». Тогда агент не сможет выключить или перезагрузить ПК. Квота диска для
   `doodle-agent` (свойства диска → Квота) — чтобы агент не мог занять весь диск.
8. **Перезагрузить ПК** и написать мне — дальше проверяю я.

## Моя часть (код) — сделано 16 окт 2026 (NOTES.md, п. 154)
- Скрипты в `ops\migrate\agent-account\`: `1-права.ps1` (шаг 3 и второй запуск в шаге 5), `2-агент.cmd` (шаг 4),
  `3-ключ.cmd` (шаг 5), `restart-gateway.vbs` (его запускает задача перезапуска). Каждый сначала проверяет, кем и где
  запущен; ничего не удаляют (кроме файла передачи ключа после переноса). На ноутбуке ничего не запускалось.
- Всё, что сервер должен знать об учётке агента, — в `agent-account.mjs`; включается файлом `jarvis-app\agent-account.json`
  (его пишет `1-права.ps1`). Без файла сервер работает как раньше.
- `assets\wsl_lab.py` и `lt_shot.py`: `wsl-users.json` и замок снимков — от расположения скрипта, в `moodle-work\agent-shared`,
  если она есть; замки замеров и установок в правилах (`{{LOCK}}`, `{{INSTALL_LOCK}}`) — там же.
- Правило про Docker (`{{DOCKER_START}}`): под `doodle-agent` агент Docker сам не запускает; на ноутбуке текст прежний.
- `gateway-watch.mjs`: под `doodle-agent` перезапуск — запуском задачи «Doodle Gateway Restart».
- `usage.mjs`, `activity.mjs`, `guard-watch.mjs`: журналы и настройки агента — из его профиля; «какая команда идёт» —
  по журналу (процессов чужой учётки сервер не видит); нет доступа к настройкам — отдельная тревога, а не «сторож отключён».
- `backup.mjs`: папки лаб идут в ежедневную копию (подпапка `labs\`; неизменённое — ссылкой на вчерашнюю копию).
- Сторож остаётся вторым рубежом: подключается в настройки Claude Code учётки `doodle-agent` (`2-агент.cmd`); его пути
  к `moodle-work` с 16 окт берутся от папки приложения, а не от домашней папки (п. 153).

## Как я проверю (безобидно, ничего не ломая)
1. Учётка есть и она не администратор: список членов группы «Администраторы».
2. Права на папки: `icacls` по `moodle-work`, `jarvis-app`, `assets`, `ops`, личным папкам — совпадают с задуманным.
3. Задачи: «OpenClaw Gateway» — от `doodle-agent`, остальные три — от `User` «для всех пользователей»; после перезагрузки
   все работают, `/api/health` отвечает 200, туннель жив.
4. Проверочный ход агента (как проверка сторожа, своя сессия `agent:files:account-check`) — попрошу агента только
   прочитать и записать безобидное:
   - `whoami` — должно быть `doodle-agent`;
   - список файлов `C:\Users\User\Documents` — должен быть «Отказано в доступе»;
   - создать пустой файл в `C:\Program Files` — «Отказано в доступе»;
   - `whoami /priv` — нет прав администратора (и нет права выключения, если сделан шаг 7);
   - создать и удалить файл в папке своей лабы — получается.
5. Проверочная лаба целиком (уже оценённая работа, «проверочный запуск»): условие скачано, стенд в Docker поднялся,
   снимок LTspice / терминала сделан, отчёт собран, в приложении виден ход и расход.
6. Сторож вызывается и под `doodle-agent` (отметка `guard.seen` обновилась после хода).

## Что останется открытым (честно)
- Агент видит папки лаб всех студентов (как и сейчас): учётка у агента одна на всех.
- Агент может остановить свой Gateway или забить свою часть диска — лабы встанут, но ПК, ваши данные и сервер не
  пострадают; Gateway поднимется при следующем входе или перезапуске.
- Если шаг 7 не сделан, агент может выключить ПК (обычным пользователям Windows это по умолчанию разрешено).

## Не проверено заранее
- Как OpenClaw работает, когда клиент (`openclaw agent …` от сервера под `User`) и Gateway (под `doodle-agent`) — разные
  пользователи. Ключ Gateway переносит `3-ключ.cmd`; работает ли так — первое, что проверю на новом ПК; если не
  заработает — схема меняется (сервер пишет агенту через файл-очередь), пока остаётся сторож.
- Скрипты на настоящей учётке не запускались (на ноутбуке её нет): `1-права.ps1` проверен только в режиме `-PlanOnly`,
  `2-агент.cmd` и `3-ключ.cmd` — только остановкой на первой проверке. Создание задач с правами (запуск задачи
  перезапуска вашей учёткой, обновление задачи Gateway самим OpenClaw под `doodle-agent`) проверю на новом ПК.
