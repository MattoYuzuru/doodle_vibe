# Перенос сервера Doodle с ноутбука на отдельный ПК

Решение владельца от 3 окт 2026. Причины: сон ноутбука срывает лабы, чужие лабы ставят программы и запускают код рядом с
личными данными владельца, снимкам LTspice нужен незаблокированный экран, на C: ноутбука свободно ~10 ГБ.

## Шаг 1. Проверка нового ПК (сейчас)
`doodle-proverka.zip` → на новом ПК запустить `doodle-proverka.cmd` (один файл; работает и прямо из окна архиватора) →
отчёт `doodle-check-result.txt` появляется на рабочем столе и открывается в Блокноте → текст прислать в чат.
Файл собирается из `check-new-pc.ps1`: шапка cmd читает саму себя как UTF-8 и выполняет часть после метки `#==PS==#`
(первая версия была из двух файлов — владелец запустил .cmd из WinRAR, и второй файл во временной папке не нашёлся).
Скрипт ничего не меняет: Windows и сборка, память, процессор, виртуализация, диски, учётная запись, питание, сеть, что
уже установлено, шрифты, доступность Moodle / Telegram / Claude / npm / PyPI / GitHub / Docker Hub.
На ноутбуке прогон дал: подходит, 3 замечания (C: 10 ГБ, но D: 181 ГБ; батарея; только Wi-Fi).
На новом ПК имя пользователя, судя по пути в первой попытке, начинается на «Aleksa…» — не `User` (см. шаг 4).

## Новый ПК: что показала проверка (3 окт 2026, первая версия скрипта)
Windows 10 Pro 19045 (RDP доступен), Ryzen 5 3600 (6 ядер/12 потоков), 23,9 ГБ памяти, виртуализация включена, стационарный.
Пользователь `Aleksandr` (не `User`). C: свободно 38 из 465 ГБ; D: 1047 из 1863 ГБ (видимо, HDD). Сон через 30 мин.
Сеть: только Wi-Fi со скоростью соединения 6,5 Мбит/с (очень слабый сигнал). Часовой пояс Москва.
Есть: winget, Python 3.12.3, Java 1.8 (нужна 17), .NET SDK 8, Word, оба шрифта. Нет: Node.js, Git, Docker, WSL, Claude Code, OpenClaw.
Интернет: Claude (api и claude.ai), GitHub, Docker Hub — отвечают; Moodle, Telegram, npm, PyPI — «не удалось разрешить имя»,
misis.ru — таймаут. В те же минуты с ноутбука Telegram и misis.ru тоже отваливались по таймауту, а сервер писал «moodle:
прямой путь не отвечает три раза подряд» — то есть сбоила сама сеть, и вывод о новом ПК по этим строкам делать нельзя.
Открыто: кабель вместо Wi-Fi и повторный прогон (вторая версия скрипта показывает потери до роутера, DNS, прокси/VPN);
чей это ПК и кто им пользуется; освободить место на C: или держать Docker на D:.

Повторная проверка (кабеля нет, Wi-Fi 21,7 Мбит/с): до роутера 0 потерь из 10, 1 мс; DNS находит все имена; прокси и VPN нет.
SSD — это C: (Kingston NVMe 466 ГБ), D: — HDD Seagate 2 ТБ. Moodle и misis.ru — таймаут, но в ту же минуту с ноутбука
Moodle тоже не отвечал 3 из 3 (в server.log 61 запись «прямой путь не отвечает») — сбой на стороне МИСИС. Telegram с ПК —
таймаут, с ноутбука отвечал. Вывод: ПК и его сеть исправны; Telegram перепроверить перед переключением.
Владелец: ПК личный, пользуются редко, может работать круглосуточно, ноутбук ездит по разным сетям. Данные — на D:.
Набор для старта на новом ПК: doodle-start-PK.zip (СТАРТ-НА-НОВОМ-ПК.md, ПЕРЕНОС.md, проверка, версии программ, pip freeze).
На ноутбуке нет `C:\Program Files\LibreOffice\program\soffice.exe`, хотя правила бота на него ссылаются — проверить.

## Шаг 2. Программы на новом ПК
Node.js 24, Python 3.12 (+ пакеты: `pip freeze` с ноутбука), Git, Java 17, .NET SDK 9, Docker Desktop + WSL Ubuntu,
LibreOffice (Word — если есть лицензия; иначе конвертация только через LibreOffice), k6, 7-Zip, cloudflared,
OpenClaw (`npm i -g openclaw`) и вход в подписку Claude (claude-cli), Claude Code + Remote Control для удалённой работы.
Установку с правами администратора (Docker, WSL) запускает владелец.
- Python — именно в `C:\Program Files\Python312\python.exe` (official.mjs ищет его там, иначе берёт `python` из PATH);
  пакеты расписания `pip install --user xlrd openpyxl`. Кэш `schedule-cache\official\` не копировать — скачается сам,
  `parity.json` пересоздастся после первой сверки с «Дневачом».
- Шрифты для снимков терминала: `C:\Windows\Fonts\CascadiaMono.ttf` и `seguisym.ttf` (render_ps.py, render_wsl.py); на
  Windows 10 Cascadia Mono может не быть — ставится бесплатно (проверяет check-new-pc.ps1).
- WSL для курса ОКСП: дистрибутив `Ubuntu` (`wsl -d Ubuntu`), systemd включён, Docker Desktop с WSL-интеграцией для
  Ubuntu (группа docker), в Ubuntu — git, python3, script.
- Docker Desktop: в lab-instruction.md вписан путь `C:\Users\User\AppData\Local\Programs\DockerDesktop\Docker Desktop.exe`
  (на ноутбуке он стоит «для пользователя»); на новом ПК поставить так же или поправить строку в правилах.
- Windows PowerShell 5.1 в PATH: activity.mjs раз в 30 с вызывает `powershell Get-CimInstance Win32_Process`.

## Шаг 3. Что копируется с ноутбука (в момент переключения, когда лаб нет)
- `C:\Users\User\moodle-work\jarvis-app\` — код, `bot-token.txt`, `users\` + `users.key`, `jobs\`, `notify\`, `lessons\`,
  `course-styles\`, `lab-allowlist.txt` (без `node_modules` и `web\node_modules` — ставятся заново; `web\dist` взять).
- `C:\Users\User\moodle-work\tools\` (переносные: Octave, LTspice, Digital, ngspice, Graphviz, PlantUML).
- Рабочие папки лаб: `C:\Users\User\moodle-work\<число>\` и `users\`.
- `C:\Users\User\.openclaw\` (настройки агентов; вход в Claude на новом ПК делается заново).
- `%LOCALAPPDATA%\LTspice\lib` (или распаковать `tools\ltspice\lib.zip` заново).
- Архив содержит секреты (токен бота, токены Moodle пользователей): только флешка или локальная сеть, не облако и не чат.
- `C:\Users\User\moodle-work\wsl-users.json` (tgId → Linux-пользователь) и домашние папки студентов в WSL. Сейчас там
  только пользователь владельца `user` с `~/oksp-lr2`; переносить целиком (`wsl --export`) стоит, только если есть
  незаконченные лабы в Linux, иначе пользователи заведутся заново (`wsl_lab.py setup`).
- `notify\<tgId>.json` хранит и снимок расписания: без него первая проверка просто молча запомнит расписание заново.
- Сеть: users.mjs ходит в Moodle «напрямую», привязываясь к адресу интерфейса шлюза по умолчанию; без VPN на новом ПК
  работает и так. `ops\misis-route.ps1` (маршруты мимо VPN) на ноутбуке задачей так и не установлен — на новом ПК нужен,
  только если там будет VPN. Часовой пояс любой: время в сообщениях считается по Москве.

## Шаг 4. Настройка
- Учётная запись Windows лучше `User` (иначе поправить `C:\Users\User` в lab-instruction.md, env-instruction.md,
  assets\lt_shot.py, assets\dig_logic.py, tools\README.md; Java — путь `D:\Android\jdk17` в dig_logic.py и README).
- Задачи Планировщика: Jarvis App Server, Jarvis App Watchdog, Jarvis Tunnel, OpenClaw Gateway.
- Автовход, сон «никогда», экран не блокировать (нужно снимкам LTspice). Удалённый экран — не RDP (он блокирует
  консоль), а AnyDesk / RustDesk / Chrome Remote Desktop.

## Шаг 4а. Отдельная учётная запись для агента (защита, добавлено 4 окт 2026)
Зачем: агент лаб выполняет команды на ПК, а рядом лежат ключ `users.key` и токены Moodle всех студентов, токен бота,
вход в Claude. Сейчас его сдерживают правила (текст) и сторож `ops\agent-guard\guard.mjs` (перехватчик Claude Code:
ловит обращения к папке приложения, `.openclaw`, `.claude`, `.ssh` — но только по упоминанию пути в команде; путь,
собранный по частям, он не распознает). Настоящая перегородка — права Windows: агент работает под другим пользователем,
которому папка приложения просто недоступна.

Что нужно (делает владелец — нужны права администратора; на новом ПК удобнее всего сразу при настройке):
1. Создать обычного (не администратора) пользователя Windows, например `doodle-agent`.
2. Службу OpenClaw Gateway (задача «OpenClaw Gateway») запускать от его имени: агента и его команды запускает именно
   Gateway, поэтому они унаследуют этого пользователя. Сервер приложения (задача «Jarvis App Server») остаётся под
   владельцем. Вход в Claude (`claude` → login) выполнить под `doodle-agent` — подписка привязывается к пользователю Windows.
3. Права на папки: `moodle-work\` (папки лаб, `tools\`) — `doodle-agent` может читать и писать; `moodle-work\jarvis-app\` —
   доступ закрыт, кроме чтения `jarvis-app\assets\`; профиль владельца (`C:\Users\<владелец>\`) ему и так недоступен.
4. Сервер пишет файлы в папки лаб (условие, вложения) под владельцем, агент — под `doodle-agent`: на `moodle-work\`
   нужны права на запись обоим.
5. Проверить пробной лабой и командой от имени агента: `type …\jarvis-app\users.key` должна дать «Отказано в доступе».
Не проверено заранее: как OpenClaw ведёт себя, когда клиент (`openclaw agent …`, его запускает сервер под владельцем) и
Gateway работают под разными пользователями; WSL и Docker Desktop у второго пользователя (агент окружения ставит пакеты
в WSL). Это проверяется на новом ПК до переключения; если не заработает — остаётся сторож.

## Шаг 5. Переключение
Дождаться конца лаб → на ноутбуке остановить задачи (сервер, туннель, Gateway) и ОТКЛЮЧИТЬ их автозапуск: два сервера с
одним токеном бота и одной подпиской одновременно работать не должны → скопировать → запустить на новом ПК → проверить
(`/api/health`, туннель, расписание, пробная лаба) → неделю ноутбук в запасе.
