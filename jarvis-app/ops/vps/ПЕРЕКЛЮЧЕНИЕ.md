# Переключение бота Doodle с ноутбука на VPS

Подготовлено 17 окт 2026. Само переключение — только по команде владельца.

## Итог: переключено 17 окт 2026 (~18:35 UTC)

- Бот, уведомления, беседы и Mini App работают на VPS; данные перенесены; лабы выключены (`LABS_OFF=1`).
- На ноутбуке отключены задачи «Jarvis App Watchdog», «Jarvis App Server», «Jarvis Tunnel» (Gateway OpenClaw не трогали).
  Не включать, пока бот на VPS: два сервера с одним токеном нельзя.
- **Mini App — через туннель Cloudflare, а не через sslip.io.** У владельца (и у многих студентов) Telegram работает
  только через VPN, а соединения из VPN до российского сервера режутся: по прямому адресу приложение не открывалось,
  до сервера не доходило ни одного запроса. Быстрый туннель (`doodle-tunnel.service`) сервер держит наружу к
  Cloudflare (узел в Москве), адрес пишется в `tunnel.log`, кнопку меню у всех `tunnel-url.mjs` переставляет сам;
  `APP_URL` в `doodle.service` поэтому закомментирован. Постоянный адрес — свой домен за Cloudflare (именованный туннель).
- «Сессия» была пустой: `curriculum_pdf.py` нужен `pymupdf` — на сервере `apt install python3-pymupdf`. Из Python
  серверу нужны только `pymupdf`, `xlrd`, `openpyxl` (пакеты `python3-*` из Ubuntu).
- **Календарь не работает:** ngrok не пускает агентов с российских IP (`ERR_NGROK_9040`), служба `doodle-calendar`
  выключена. Подпиской пользовался только владелец. Решение — перевести ленту на адрес сервера (нужно решение владельца).
- **Настройка после переключения (17 окт, вечер; владелец остаётся на этом сервере, баланс пополнен до ~25 ноя):**
  - Caddy выключен (`systemctl disable --now caddy`), правила ufw для 80/443 удалены: снаружи открыт только
    `tailscale0`, адреса sslip.io больше нет. `current-url.txt` и кнопка меню — адрес туннеля, их это не задело.
  - Сторож `doodle-health` (`doodle-health.sh` → `/usr/local/bin/doodle-health`, `doodle-health.timer` — раз в 5 мин):
    doodle и ответ 127.0.0.1:8787, туннель (адрес из `tunnel.log` открывается снаружи), память < 120 МБ, диск ≥ 85 % —
    сообщение владельцу в Telegram, повтор не чаще раза в 6 ч, «✅» когда прошло. Проверка отправки: `doodle-health test`.
  - Drop-in `/etc/systemd/system/doodle.service.d/alert.conf` (копия — `doodle-alert.conf`): 5 падений за 10 минут —
    systemd перестаёт поднимать doodle и шлёт 🛑 (`doodle-health-failed.service`). Поднять снова:
    `systemctl reset-failed doodle && systemctl start doodle`. При отладке с частыми перезапусками помнить про предел.
  - Автобэкапы Timeweb: весь диск, ежедневно в 00:15 МСК, 3 копии, 270 ₽/мес (вкладка «Бэкапы» сервера). Плюс своя
    ежедневная копия данных `backup.mjs` в `jarvis-app/backups` (14 дней, тот же диск).
- Владельцу: убрать кнопку меню в @BotFather (Bot Settings → Menu Button → Remove), иначе новые пользователи видят
  старый адрес.

Сервер: Timeweb `doodle-test`, Москва, Ubuntu 26.04. Вход с ноутбука: `ssh doodle` (root) и `ssh doodle-app`
(пользователь приложения), оба через Tailscale. Код на сервере — `/home/doodle/moodle-work`, служба `doodle`,
Mini App — через туннель Cloudflare (Caddy и sslip.io выключены 17 окт). Сейчас на сервере нет ни токена бота, ни данных пользователей.

## Решения до переключения

1. **Лабы.** На сервере нет агента (OpenClaw, Claude, LTspice, WSL). Решение владельца (17 окт 2026): переключаться
   до исполнителя, лабы временно выключены. Выключатель — `LABS_OFF=1` в `doodle.service` (или файл `labs.off`
   рядом с сервером, действует без перезапуска): начать, исправить, написать агенту, «Кратко о работе», проверка
   отчёта и одобрение установки окружения отвечают `labs_off`, приложение показывает «Отчёты с агентом временно
   недоступны». Готовые отчёты открываются, подтверждаются, прикрепляются и отправляются в Moodle как обычно.
   Проверка — `node ops/stand/labs-off-test.mjs`. Вернуть лабы — убрать `LABS_OFF` после исполнителя.
2. **Адрес.** Временный https://72-56-249-191.sslip.io: привязан к IP сервера. Свой домен можно взять потом:
   сменить имя в `ops/vps/Caddyfile` и `APP_URL` в `ops/vps/doodle.service`, кнопки меню сервер поправит сам.
3. **Календарь.** Подписки студентов ведут на постоянный домен ngrok из `calendar-base.txt`. На сервере его
   держит служба `doodle-calendar` (`ops/vps/doodle-calendar.service`). У бесплатного ngrok один агент на аккаунт,
   поэтому включать её только после остановки сервера на ноутбуке.

## Что доработано в коде

- `tunnel-url.mjs`: постоянный адрес из переменной `APP_URL`. Если она задана, `tunnel.log` не читается, а кнопки
  меню (по умолчанию и у каждого пользователя) и `current-url.txt` держатся на этом адресе; владельцу одно
  сообщение «Постоянный адрес Doodle: …». Проверка — `node ops/stand/tunnel-url-test.mjs` (без настоящего Telegram).
- `server.mjs` и Mini App (`Lab.tsx`, `DeadlineDetails.tsx`, `Check.tsx`, `lib/labGate.ts`): выключатель лаб (п. 1).
- `ops/vps/doodle.service`: добавлены `APP_URL` и `LABS_OFF=1`. Остальные Windows-части выключены переменными (`CAL_TUNNEL=0`,
  `GUARD_WATCH=0`, `MOODLE_DIRECT=0`, `PYTHON`).

## Данные (папка `jarvis-app` на ноутбуке)

Переносить:

| Что | Зачем |
|---|---|
| `bot-token.txt` | токен бота (секрет) |
| `bot-updates.on` | сервер сам получает сообщения боту (/start, команды, беседы) |
| `users/`, `users.key` | пользователи: токены Moodle, пароли журнала (зашифрованы ключом), ФИО (секрет) |
| `cloud/` | копии личных данных приложения (дедлайны, заметки) |
| `notify/` | настройки уведомлений и снимки расписания (без них первая проверка молча запомнит всё заново) |
| `chats.json` | привязанные беседы и их расписание |
| `lessons/`, `usage/`, `quality/`, `course-styles/` | замечания, лимиты, оценки качества, стили курсов |
| `announce-session-state.json`, `bot-move-state.json`, `welcome-media.json` | кому что разослано, медиа приветствия |
| `deadlines-cache/` | копии дедлайнов: сервер стартует с ними, не дожидаясь Moodle |
| `jobs/`, `checks/`, `lab-allowlist.txt` | история лаб и проверок (нужна, если лабы будут видны в приложении) |
| `ngrok.yml` | ключ ngrok для календаря (секрет) |

Не переносить: `bot-token-prev.txt` (прежний бот, прощание отправлено), `backups/` (сервер делает свои копии),
`schedule-cache/`, `cal-cache/` (скачаются заново), `ej-debug/`, `diag/`, `current-url.txt` (у сервера свой),
`ngrok-token.txt`, `tunnel-nobind.flag`, `notify-state.old.json`, журналы `*.log`.
Лабы владельца на ноутбуке (`moodle-work\<число>\`, `moodle-work\users\`, `wsl-users.json`) остаются у исполнителя.

Перенос — только архивом по `scp` через Tailscale (шифрованный канал между своими устройствами), не через облако,
GitHub или чат. Архив после распаковки удалить с обеих сторон.

## Порядок переключения (около 20 минут)

1. Проверить, что не идёт ни одна лаба (`jobs/*.json` со статусом `running`) — иначе ждать.
2. На ноутбуке в Планировщике **отключить** задачи «Jarvis App Watchdog» (иначе поднимет сервер обратно),
   «Jarvis App Server», «Jarvis Tunnel»; остановить процессы сервера, cloudflared и ngrok календаря.
   Два сервера с одним токеном одновременно работать не должны: бот начнёт терять сообщения.
3. Собрать архив данных из таблицы выше (после остановки — чтобы файлы не менялись во время копирования).
4. `scp` архива на сервер, распаковать в `/home/doodle/moodle-work/jarvis-app` под пользователем `doodle`,
   права `600` на `bot-token.txt`, `users.key`, `ngrok.yml`; удалить архив.
5. Отправить код (`git push vps main`), на сервере `git pull` и `npm run build` в `web`; установить обновлённую `doodle.service`,
   поставить ngrok и включить `doodle-calendar`; `systemctl restart doodle`.
6. Проверить:
   - `curl https://72-56-249-191.sslip.io/api/health` → `botToken: true`;
   - в `server.log` строка `menu button → https://72-56-249-191.sslip.io`, владельцу пришло «Постоянный адрес Doodle»;
   - `/start` и `/deadlines` боту отвечают; Mini App открывается **с телефона** (с ноутбука через VPN адрес не открывается);
   - ссылка календаря из приложения отдаёт `.ics`; в беседе «Кирпичи» работает `/today`.
7. Неделю ноутбук в запасе (задачи отключены, данные на месте).

## Откат

На сервере `systemctl disable --now doodle doodle-calendar`; на ноутбуке включить три задачи и запустить сервер.
Всё, что изменилось на сервере после переключения (новые пользователи, уведомления), перед этим скопировать обратно
тем же способом — иначе пропадёт.

## Через неделю после переключения

Удалить с ноутбука `jarvis-app\users\`, `users.key`, `bot-token.txt`, `backups\` (политика обещает, что пароли после
выхода не живут дольше 14 дней) и решить, что делать с пробным названием сервера и временным адресом.
